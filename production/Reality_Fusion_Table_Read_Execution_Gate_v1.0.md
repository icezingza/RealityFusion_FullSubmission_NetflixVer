## Purpose

This gate defines the exact conditions required before any timed Thai table read may be treated as valid evidence for runtime and screenplay-lock decisions.

## Minimum personnel

A valid session requires, at minimum:

1. Khru Ba Ice reader;
2. NaMo reader;
3. younger-character reader;
4. Ethari / institutional-character reader;
5. supporting-adult / community reader;
6. independent timekeeper / note-taker.

One person may cover multiple supporting roles, but the timekeeper must not be simultaneously performing a principal role.

## Timing evidence required

For each episode, record:

- session date;
- exact PDF filename and draft version;
- start timestamp;
- end timestamp;
- correction / restart time;
- interruptions not belonging to performance;
- intentionally held silence;
- archive-audio duration where actually read aloud;
- interface-text reading treatment;
- raw elapsed duration;
- net table-read duration;
- notes on likely visual-only expansion or compression.

No runtime number may be accepted if any of the above fields is missing.

## Reading rules

- Read the screenplay as written.
- Do not rewrite dialogue during the timed pass.
- Do not skip action lines merely because they are visual.
- Do not add performance improvisation into the official timing result.
- Mark pronunciation problems separately from writing problems.
- Mark performance problems separately from structural pacing problems.
- Complete the episode log before revising the screenplay.

## Episode-specific escalation flags

### EP1

Escalate if Buddhist / monastic terminology or ritual staging appears doubtful.

### EP2

Escalate any concern involving child safeguarding, consent, privacy, or school procedure. Table-read feedback cannot certify these areas.

### EP3

Escalate medical, cardiology, palliative-care, clinical-death, funeral, or monastic-practice questions.

### EP4

Escalate technology, memory continuity, synthetic-voice, or institutional-procedure questions.

### EP5

Escalate governance, privacy, emergency-access, network-control, child-participation, or AI-authority questions.

## Acceptance gate

An episode may move from `PENDING EXTERNAL PROCESS` to `MEASURED` only when:

- the authorized current PDF was used;
- all required timing fields were completed;
- the episode-specific log is complete;
- interruptions and correction time are separated from the net read;
- unresolved specialist questions are explicitly flagged rather than solved by the table-read group.

The consolidated runtime report may be populated only after all five episode logs meet this gate.
